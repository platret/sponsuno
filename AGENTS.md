# AGENTS.md – Sponsuno website

Read this first in every session. It says what this project is, how it is built, and which rules are not negotiable. Visual rules live in [DESIGN.md](DESIGN.md); read that before touching anything visible.

## What this is

Sponsuno is a startup project of a four-person team in the programme Youngpreneurs Zürich 2026/27 (https://youngpreneurs.org/zuerich/). The planned platform matches athletes, sport clubs and culture clubs with sponsors from their region, starting in German-speaking Switzerland (long term: DACH). A personal AI sponsoring manager is planned to help with the partnership afterwards, plus separately billed marketing services (photo, video, content).

This repo holds:

1. The public **landing page** (`/`). It explains the idea and collects interest on a waitlist. Since 2026-11-18 it is the «Turnhalle» page (design system v2, owner's direction of 2026-11-17: alive, little text, stickers, court lines, scroll effects; cleaned up on 2026-11-18 after the owner's «stickers are okay but a bit of a gimmick, make it look cleaner»: six small stickers, flat tags, thin lines, see DESIGN.md → «The clean rules»): seven short blocks (header, hero, statement, word band, how it works in three steps, the two doors, waitlist + footer); the rest lives on topic pages.
2. Three **topic pages** reached from the header: `/kosten/` (with "Nicht nur Geld"), `/fragen/`, `/ueber-uns/` (team and project status).
3. The legal pages `/impressum/` and `/datenschutz/`.
4. A **404 page** (`dist/404.html`), which Cloudflare serves with status 404 for every unknown URL.
5. The **waitlist route** `POST /api/warteliste` (Cloudflare Worker, `worker/`) for the Brevo double opt-in, and its landing page `/warteliste/bestaetigt/` (noindex). Live since 2026-11-17 (copy rule 11; see "Waitlist" and "Deploy").
6. **Parked sources** (not built, not linked, not reachable; see "Parked (not built)"): the topic pages `/fuer-firmen/` and `/ki-manager/`, the four guide pages (Ratgeber) with their Word templates, and the clickable product preview (`/demo/`, `src/demo/`).

**The product does not exist yet.** No page may claim that it works today. Since 2026-11-10 the site still reads like a confident SaaS page before its launch (see "Rules for copy": product voice, one launch signal per page).

- Live: https://sponsuno.ch (www.sponsuno.ch redirects to sponsuno.ch)
- Repo: https://github.com/platret/sponsuno (public)
- Language of the page: German, Swiss spelling, formal "Sie"

## Commands

Node 22.18 or newer (`engines` in `package.json`; CI uses the latest 22): `npm test` relies on Node's built-in TypeScript type stripping, and `@axe-core/playwright` 4.14 needs 22.12.

```bash
npm install
npm run dev        # http://localhost:5173/
npm run build      # typecheck, client build, prerender into dist/
npm run preview    # serve dist/ at http://localhost:4173/
npm run typecheck
npm run fonts      # only after changing the font subsets: rewrites src/assets/fonts/ and src/styles/fonts.css (commit them)
npm run photos     # only after replacing a photo in src/assets/photos/: rewrites its AVIF versions (commit them)
npm test           # unit tests of the Worker (worker/*.test.ts, node --test, Brevo mocked)
```

`npm run build` must pass before every commit. CI also runs `npm run typecheck`, `npm test`, `npm run check:dist`, a `wrangler deploy --dry-run` and `npm run test:e2e` on every PR (see "CI"); still verify visual changes in a browser (see "Before you finish").

## Architecture

Vite 8 (Rolldown) + React 19 + TypeScript (strict). No UI framework, no CSS framework. One small Cloudflare Worker script (`worker/`) answers `/api/*` only; everything else is static assets. `vite` and `@vitejs/plugin-react` are pinned to exact versions, and `overrides` in `package.json` pins Rolldown (Vite allows newer patches): take only releases at least two weeks old, and move the pins together.

### Conventions that the code relies on

- **What the landing page bundle carries**: `main-*.js` imports `content.ts`, and the bundler keeps only what the landing page code reads. Never read `guides`, `legal` or other page-only objects from code the landing page reaches (`App.tsx` and its components, or a top-level constant in `content.ts` that one of them uses), and never index them with a variable key (`guides[id]` keeps every guide): either ships that whole text to every visitor. Use the small exports instead: `contact` (address and e-mail; `legal.contact` is the same object), `guideTitles` (the guides' H1s), `pageMeta()`. `npm run check:dist` fails when a script of the landing page (the module script, its modulepreloads and everything they import statically) contains a marker sentence of the legal pages or the 404 page (`FOREIGN_TEXT` in `scripts/check-dist.mjs`; the parked guides and `/fuer-firmen/` get theirs back when they are built again). Known leftovers: `pages.ts` (with `parkedPages`) and a few top-level constants of parked content that call `pageMeta()` (the bundler cannot prove them pure) are in `main-*.js`; small, within budget.
- **Copy** comes from `src/content.ts` (landing page: `hero`, `statement`, `wordband`, `steps`, `match`, `doors`, `waitlist`, `album`, `stickyCta`, `footer`). Exceptions: a few accessibility labels are inline (skip link in `App.tsx`, nav and logo labels in `Header.tsx`, `aria-label` in `Footer.tsx`, the footer wordmark). Check those too when reviewing copy. The Easter-egg strings are `album.title`, `album.hint`, `album.full` and `album.goal` (the word on the «tor» scoreboard); the score after it is counted in the browser. Parked content (`story`, `problem`, `audience`, `howItWorks`) stays exported while the parked sources exist, because `tsc` compiles everything under `src`. `proof` is live: `statement.points` reads `proof.items`, the word band `proof.disciplines` and `proof.disciplinesLabel`. Two places tie layout to copy and say so loudly: `WordBand.tsx` puts the band's one sticker (the note) on «Kultur» and stops the build unless row one is exactly two words ending in that word; `wordband.css` sizes the lockup from the glyph widths of the words (re-measure its divisors when a word changes; e2e checks which words stand whole in the band at rest). `Steps.tsx` draws its three line drawings by position in `steps.items` and stops the build when the counts differ (no text from `content.ts` is drawn into them: «4 von 4» stands only in the match card). `MatchCard.tsx` picks the criteria icons by position in `match.criteria`.
- **SSR-safe components**: the page is prerendered at build time. Never touch `window`, `document`, `matchMedia` or `localStorage` at module top level or during render; only inside effects or event handlers.
- **Motion gate**: `html.motion` is set only when the visitor does not prefer reduced motion (`motionEnabled()`). `html.scroll-fx` is set on top of it only when the browser supports `animation-timeline: view()` (`scrollFxEnabled()`). Exception: the parked `/ki-manager/` sets `html.scroll-fx` alone (see "Topic pages"). Every animation needs a still fallback that shows the final state: the static styles of an element are its final state, keyframes describe only where it starts.
- **Scroll motion** (plan, primitives and fallbacks in DESIGN.md → Motion): the kit's primitives are `data-scroll="draw"` (court lines draw with the scroll), `"fill-words"` (words fill from grey to ink) and `"slide-x"` (a row slides sideways, to `--slide`); the base primitives of `site.css` (`rise | fade | zoom-in | photo | frame | draw-x | draw-y | recede | group`) remain, with `data-reveal=""` next to them where browsers without scroll timelines should still get the fade. Tune with the documented custom properties (`--draw-*`, `--fill-*`, `--slide*`, `--scroll-*`), never by copying the primitives. Section-specific scroll animations go in the section stylesheet under `.scroll-fx` and use `animation-timeline: view()`, `scroll()` or a named `view-timeline`; set `animation-timeline` and `animation-range` after any `animation` shorthand (the shorthand resets them). Allowed properties: `opacity`, `translate`, `scale`, `rotate`, `clip-path`, and for the three kit effects `color` / `background-color` (fill-words), `stroke-dashoffset` / `stroke-dasharray` (draw) and `offset-distance` (the door ball). One `data-scroll` per element; never on an element that has its own CSS animation (wrap it). Every element must be final once it is comfortably in view (about 50 to 60 % down the viewport), and nothing visible at scroll 0 may start hidden or half-animated: where a block can be in view at load (tall screens) its effect starts whole or is switched off by a `min-height` query (`statement.css`). Named `view-timeline`s set `view-timeline-inset: 0px`; never put `scale`/`translate` animations on an SVG element (wrap it in a `span`). A shared focus guard in `site.css` shows any `data-scroll` block holding focus in its final state; do not add per-section copies. No pinned sections on the landing page. Nothing starts by itself and runs longer than 5 s.
- **Kit** (`src/components/kit/`, `src/styles/kit.css`; details in DESIGN.md → Kit): `Sticker` (ids in `STICKER_IDS`: ball, note, brezel, startnummer, wimpel, pfeife; `collectable` defaults to true, pass `collectable={false}` for a sticker that is only illustration; `Vars` is the one type for style objects with custom properties, import it instead of redeclaring it), `Tag` (the flat label: tones gelb, blau, rot, gruen, tinte, parkett and the outlined `linie`, optional `dot`, size via `--tag-fs`; it replaced the tilted `TextSticker`, which is gone), `Icon` (`ICON_NAMES`), `CourtLines` (variants hero (the corner arc), band (prop `line` for its colour; also the hero's base line, as two strips), door-sport, door-firma; every line sits in a box no larger than it needs, never behind text). All decoration is `aria-hidden`. **The clean rules bind every change** (DESIGN.md → «The clean rules»; e2e checks them at four widths): exactly six picture stickers on the landing page, each id once, all collectable, at most 96 px (72 px on phones) and 8° of tilt, at rest and in motion; nothing else is rotated (labels are `Tag`s); court lines are thin (one weight, `--cl-w`), at most two line colours per block, never behind a headline, text, button or form field (the hero's base line has a gap for the round arrow); a static page has one small sticker in its page head band and no other. Adding a sticker anywhere means taking one away. A sticker's size is set inline: for a responsive size set `inline-size` on a selector more specific than `.stk`. `rotate` and `scale` on `.stk` belong to the kit; code that moves a sticker uses `translate`. Words drawn as outline text (the word band) come from CSS `content: attr(data-word)`, never from real transparent text (axe would report it).
- **Easter eggs** (`lib/eggs.ts`, `styles/eggs.css`, `components/Album.tsx`; DESIGN.md → Easter eggs): the sticker album (a click or tap on any `[data-sticker][data-collectable]` counts its id once; counter chip in the header, album `#album` in the landing page footer), dragging the hero ball (`data-draggable`, the only one, mouse only), the «tor» scoreboard, the bouncing «o» of the footer wordmark. Where the six ids are found, each exactly once: the ball in the hero (`#top`; it is draggable and collectable, the click that ends a drag does not collect), the note in the word band (`.wb`, on the corner of «Kultur»), the pennant and the pretzel in the two doors (`#fuer-wen`, inside `.door-art`; the copy's box lets clicks through where it is empty), the start number in the waitlist band (`#warteliste`), the whistle beside the album in the footer (`footer.ft`, so five of the six are in `<main>`). Statement, steps and match card render no sticker; the album's own six stickers pass `collectable={false}` and take no pointer events. Every sticker can be clicked at 1440 px and tapped at 390 px (e2e fills the album with real clicks and real taps; `STICKER_HOME` in `e2e/helpers.ts` is the list). The chip (`Header.tsx`) is the kit's flat `Tag` as a plain `span`, worn as a badge on the upper right corner of the header's waitlist button (positioned absolutely in `.header-actions`), so it always lies inside the bar, never on the page's content, and nothing in the bar moves when it appears. A dragged ball keeps clear of the hero's text and buttons (`DRAG_CLEAR` in `eggs.ts`); the whistle beside the album leaves no outline once collected. The finale is small: the chip swells once where the sixth sticker was found; the album's stickers hop once in turn when the full album is on screen (`.is-seen`, one IntersectionObserver in `Album.tsx` that exists only while a full album has not been seen). There is no burst. Rules that are not negotiable: **state in memory only** (no cookie, `localStorage`, `sessionStorage`, IndexedDB or Cache Storage; the Datenschutzerklärung says nothing is stored, and e2e checks all five), **never needed to use the page** (no content, no control and no information exists only inside an egg; the page is complete without the chunk and without JavaScript), **hidden from assistive technology and out of the tab order** (`aria-hidden`, no link, button or `tabindex` inside, nothing announced, focus never moved), **never in the way of the page's own gestures** (no listener per scroll frame; no `touch-action` override and no drag on touch: a swipe that starts on a sticker scrolls the page, e2e checks it; cursors live in `eggs.css`, not in the kit, so nothing looks clickable before the chunk runs). Every document-level listener must survive odd events (autofill dispatches `keydown` without a `key`). The chunk is fetched on `requestIdleCallback` so it never counts against the first-load JavaScript.
- **Landing page frame** (`App.tsx`, end of `header.css`): `<main>` is its own stacking context with the parquet ground and clips what a block lets stick out sideways. There is no layer under the blocks any more: the page tape line (`.page-line`, `CourtLines variant="page"`) was removed on 2026-11-18, every hall line belongs to its block (hero: red base line and blue corner arc; word band: two yellow lane lines; doors: the drawings; waitlist: one parquet line). The header turns ink while an element marked `data-header-dark` (word band, footer) crosses the line just below the bar's lower edge, and is the parquet bar everywhere else (`Header.tsx`, IntersectionObservers, no scroll handler); a band that ends exactly at the bar's edge, where an in-page link to the next block lands, does not count. In the built page the shared stylesheet (fonts, `site.css`, `footer.css`) is linked after the page's own (kit and sections): base rules sit in `@layer base` so this order never matters; never put section or kit CSS into a layer.
- **Reveals**: `data-reveal=""` alone fades an element in once (`observeReveals()` in `App.tsx`, CSS in `site.css`). Under `.scroll-fx`, elements that also carry `data-scroll` are skipped by the observer and the fade is neutralised.

- Decoration (stickers, court lines, the giant word rows, the step drawings, the album, the counter chip, the scoreboard) is `aria-hidden` and never focusable. The word band's words are available to screen readers once, as a plain list of exactly the words that are drawn (nothing is announced that is not shown).
- An in-page link moves keyboard focus to its target after the scroll has ended; the skip link's focus ring lies inside its yellow box, so it reads over the parquet hero and over the ink header of the static pages.
- Form errors are announced (`role="alert"`) and linked via `aria-describedby`.
- CI runs axe (`e2e/a11y.spec.ts`, `@axe-core/playwright`) on `/`, `/kosten/`, `/fragen/` and `/impressum/` and fails on serious or critical violations. **There is no exception for any page or element**: the landing page is scanned with reduced motion (desktop and 390 px), with motion at the top (the statement not yet filled), block by block while scrolling, at the end of the page, and with a collected sticker and the counter chip. If a scroll effect fails contrast in one of its states, fix the effect, not the test. One limit of axe to know: text it cannot measure (for example because a box lies under it) lands under `incomplete`, which fails nothing; so one test measures the unfilled statement at 1440 px wide and requires every word to be in `passes` and none in `incomplete` (it had to run at 1200 px while the page tape line lay under the statement; that line is gone). A new page type goes into `PAGES` in that file.

## Deploy

- Hosting: Cloudflare Workers with static assets (`wrangler.jsonc`, Worker `sponsuno`, serves `dist/`; the script `worker/index.ts` runs only for `/api/*`). Custom domains sponsuno.ch and www.sponsuno.ch; a Cloudflare Redirect Rule sends www to the apex.
- Push to `main` → `.github/workflows/deploy.yml` builds and runs `wrangler deploy` (production). Pull requests from this repo run `wrangler preview --name pr-<number>` and get a preview URL on workers.dev.
- GitHub secrets: `CLOUDFLARE_API_TOKEN` (account-owned token: Workers Admin, Zone › Workers Routes › Edit on sponsuno.ch) and `CLOUDFLARE_ACCOUNT_ID`.
- DNS for sponsuno.ch is on Cloudflare. Never change or proxy the Infomaniak mail records (MX, SPF, DKIM `20261103._domainkey`, `_dmarc`, `autoconfig`, `autodiscover`).
- Keep Bot Fight Mode and other cookie-setting Cloudflare features off: the Datenschutzerklärung says no cookies are set.
- Workers observability is off (`observability.enabled: false`): the Datenschutzerklärung says no per-request logging is set up.
- **Switching the waitlist on** (in this order; setup doc `../team/warteliste-setup.md`, steps 8, 11, 12): (1) the team sets the secret `BREVO_API_KEY` on the Worker (`npx wrangler secret put BREVO_API_KEY` or the dashboard) and, for tests on PR previews, `npx wrangler preview base-config secret put BREVO_API_KEY` (applies to previews created afterwards); (2) Claude puts the list ID and the DOI template ID into `wrangler.jsonc` (`vars` and `previews.vars`) and finishes the Datenschutzerklärung from the draft; (3) the team sets the repository variable `VITE_WAITLIST_ENDPOINT` to `/api/warteliste` (Settings → Secrets and variables → Actions → Variables; the deploy job already passes it to the build, the `check` job never does). A relative path, so PR previews post to their own Worker. Until (3) the form keeps the e-mail route; between (3) and (1)/(2) the Worker answers `not_configured` and the form falls back to the e-mail route by itself.
- Rate limits: two Rate Limiting bindings (`ratelimits` in `wrangler.jsonc`, namespace IDs 4801 and 4802, chosen freely, no dashboard setup; per Cloudflare location and approximate). If a deploy ever fails because of them, remove the bindings: the Worker then uses its in-memory fallback, and the honeypot stays.
- Brevo locks API keys to the IP addresses it learns in the first 30 days; a Worker has no fixed outgoing IP. The team decides how to handle this (setup doc, step 8). A sudden wave of 502 answers after a month points there (`npx wrangler tail` shows "Brevo answered 401").
